Section 01The forces

Every structural decision below traces to one of five constraints. Where they conflict, they are ranked in this order.

#ConstraintConsequence for structure
1Correctness is checkable from outside.Estimation is pure functions over accumulator state, so results are reproducible and comparable without a database or a clock.
2The core takes no dependency.Ports live in the core; every driver is an adapter in a satellite package. Dependencies point inward, always.
3Data volume is unbounded.No component may hold the series. Anything that would is a bug, not a tuning problem.
4One estimation path.The array API is a thin wrapper over the streaming accumulators, not a parallel implementation. Two paths would drift.
5It runs on the consumer's machine.No ambient configuration, no background threads, no static mutable state, no logging framework. Everything is passed in.

Section 02Layers and the dependency rule

Ports and adapters, with the estimation core at the centre. An adapter knows about the core; the core never knows about an adapter.

TimeSeries.NET.Data adapter · BCL only DbDataReader cursor, keyset paging, gap detection
TimeSeries.NET.Data.MongoDb adapter · MongoDB.Driver Aggregation-pipeline cursor
…Extensions.DependencyInjection adapter · MEDI.Abstractions Registration helpers
↓   depends on   ↓
TimeSeries.NET core · zero dependencies Ports (ITimeSeriesSource, ITimeSeriesCursor) · Estimation · Accumulators · Transforms · Solvers · Forecasting · Statistics
↓   depends on   ↓
.NET base class library net8.0 Span, Memory, ValueTask, ArrayPool, System.Data.Common

The inversion is the whole point: ITimeSeriesSource is declared in the core and implemented outside it, so the estimator depends on an abstraction it owns rather than on anybody's driver. That is what lets the core keep its zero-dependency promise while still reading from Postgres.

The rule, stated so it can be tested

The core assembly's referenced-assembly list must contain nothing outside System.*. This is asserted in a unit test that reflects over typeof(ArimaModel).Assembly.GetReferencedAssemblies(), so a well-meaning package reference fails the build rather than quietly ending the promise on the README.

2.1Internal module boundaries

Inside the core, the same direction holds. Modules may depend downward, never upward:

The four leaf modules have no internal dependencies at all, which is why they are the first things built and the easiest things to test.

Section 04Four contracts

The entire library composes from four small interfaces. Everything else is an implementation of one of them or a function over their outputs.

4.1Transform — stateful, streaming, O(warm-up) memory

public interface ISeriesTransform
{
    int WarmupLength { get; }               // rows consumed before the first output
    int Transform(ReadOnlySpan<double> input, Span<double> output);
    void Reset();
}

Differencing is the only implementation in v1. Transforms chain, so (1−B)d and (1−Bs)D compose rather than being special-cased. WarmupLength is what the partitioned reader uses to size its overlap prefix — the correctness of parallel fitting depends on this number being right, so it is the transform's responsibility to report it, not the reader's to guess.

4.2Accumulator — mergeable, serialisable, no data retained

public interface IAccumulator<TSelf, out TResult> where TSelf : IAccumulator<TSelf, TResult>
{
    void Add(ReadOnlySpan<double> row);
    void Merge(in TSelf other);       // must be exact — asserted in tests
    void Scale(double lambda);        // exponential forgetting
    TResult Freeze();                   // pure; may be called more than once
}

Merge being exact is what makes partitioned fitting and incremental folding the same operation viewed from two directions. Freeze being pure and repeatable is what lets order selection evaluate a hundred candidate models against one accumulator.

4.3Port — the only thing that knows data is remote

public interface ITimeSeriesSource
{
    int RegressorCount { get; }
    ValueTask<ITimeSeriesCursor> OpenAsync(CancellationToken ct = default);
}

ArraySource in the core implements this over a double[], which is how the synchronous API reaches the same engine without a second code path. The database adapters implement the identical interface, so every test written against ArraySource is also a test of the contract the adapters must satisfy.

4.4Solver — swappable numerics

public interface ILinearSolver
{
    bool TrySolve(ReadOnlySpan<double> gram, ReadOnlySpan<double> rhs,
                  Span<double> coefficients, out SolveDiagnostics diagnostics);
}

Gaussian elimination with partial pivoting ships in v1. The interface exists so the streaming QR described in the specification can replace it later without reaching into estimation code — and so a singular design surfaces as a false return with diagnostics rather than an exception thrown from four layers down.

Section 05A fit, end to end

One traversal, no materialisation, and a result that has forgotten where it came from.

ArimaModel.FitAsync(source, ct)
│
├─ 1  source.OpenAsync(ct)                       → ITimeSeriesCursor
│
├─ 2  while (await cursor.ReadAsync(ct))         8 192 rows per await
│     │
│     ├─ transform.Transform(batch, scratch)     difference in flight, ring buffer
│     ├─ gram.Add(row)                           (L+1)² accumulation
│     └─ autocov.Add(row)                        classical γ̂, own ranges
│
├─ 3  cursor.DisposeAsync()                      connection released here — before any solving
│
├─ 4  G = gram.Freeze()                          from here on: no I/O, pure functions
├─ 5  φ̂ = solver.TrySolve(G[1..m,1..m], …)       pilot AR(m), a submatrix
├─ 6  A = BuildProjection(φ̂, p, q)               (L+1) × (p+q)
├─ 7  solver.TrySolve(Aᵀ G A, Aᵀ G e₀, …)        ARMA coefficients
├─ 8  diagnostics: σ̂², AICc, invertibility, Ljung–Box
│
└─ 9  new ArimaFit(…)                            immutable; holds no source, no buffer

Two properties of this sequence are load-bearing. The cursor is disposed at step 3, before any numerical work, so a fit never holds a database connection while solving. And steps 4 through 9 touch no I/O at all, which is why order selection can evaluate an entire grid — different A matrices against the same G — without a second traversal.

Section 06State and lifetime

What is allowed to be mutable, and what must never hold a reference to the consumer's data.

TypeMutabilityLifetimeMay reference data?
ArimaOptionsImmutable recordCaller-ownedNo
ArimaModelStatelessReusable, any durationNo
ITimeSeriesCursorMutableOne traversal; IAsyncDisposableYes — one batch
AccumulatorsMutableOne fit, or one foldNo — sums only
ArimaFitImmutableIndefinite; serialisableNo
ForecastResultImmutableIndefiniteNo
IncrementalArimaMutableSpans folds; serialisableNo — sums and a tail

The invariant behind the table: nothing that survives a fit may reference anything proportional to the series length. An ArimaFit carries coefficients, a differencing tail of d + D·s values, and the last max(p,q) observations needed to seed the forecast recursion. That is bounded by the model order and nothing else, which is why a model fitted over 300 million rows serialises to a few hundred bytes and can be cached, shipped, or stored next to the data it came from.

There is no static mutable state anywhere in the library, and no ambient configuration. Everything a fit needs is an argument to it.

Section 07Concurrency model

Stated explicitly, because a library that leaves this to inference gets used wrongly and blamed for it.

TypeThread safety
ArimaModel, ArimaOptionsSafe. Stateless and immutable; share freely across threads.
ArimaFit, ForecastResultSafe. Immutable after construction.
AccumulatorsNot safe. One per worker, merged when all are complete.
ITimeSeriesCursorNot safe. One traversal, one consumer. Current is valid only until the next ReadAsync.
IncrementalArimaNot safe. One instance per series; folds are sequential.

7.1Parallelism across one long series

Row ranges are fitted independently and merged. Each partition reads a warm-up prefix of transform.WarmupLength + L rows before its start, uses them only to prime the ring buffer, and contributes none of them to its accumulator. Because Merge is exact, the combined result equals the single-threaded result — an asserted invariant rather than an approximation.

7.2Parallelism across many series

A single ordered scan is the producer; a bounded Channel<KeyedSeries> feeds a fixed set of worker tasks. The reader stays sequential because the ordering by (key, time) is what keeps memory at O(L²) per worker instead of per key. Degree of parallelism is a caller-supplied option defaulting to Environment.ProcessorCount, and back-pressure comes from the channel's bound — the scan cannot outrun the fitters and accumulate a backlog of buffered series.

7.3Cancellation

CancellationToken flows to every ReadAsync and is checked at batch boundaries. A cancelled fit stops within one batch — at most 8 192 rows — rather than at the end of the scan. Cursors are disposed on the cancellation path, so a cancelled fit never leaks a connection.

Section 08Extension points

Three things a contributor will want to add. None of them requires touching the estimation core.

To addImplementCore changes
A new database or file format ITimeSeriesSource and ITimeSeriesCursor in a new package None. The contract tests in TimeSeries.NET.Tests are reusable against any implementation.
A different numerical backend ILinearSolver None. Pass it through ArimaOptions.
A new model family (ETS, Holt–Winters) A new estimator in Estimation/ reusing the existing accumulators and transforms Additive. The accumulator and port layers are model-agnostic by construction.

The roadmap lists ETS and Holt–Winters after ARIMA. Neither needs a Gram matrix, but both need streaming moments, differencing, error metrics and a source — all of which already exist by then. That is the return on putting the seams where they are rather than building ARIMA as one class.

Section 10Test architecture

Three projects with distinct jobs, so a slow or environment-dependent test can never block the fast suite.

ProjectContainsNeeds
TimeSeries.NET.Tests Closed-form identities, hand-computed fixtures, parameter recovery on simulated series, committed reference constants, and the structural invariants. Nothing. Runs in milliseconds, on every commit.
TimeSeries.NET.Data.Tests Adapter conformance: ordering, gap policy, keyset paging, cancellation, connection disposal. Run against SQLite in-memory for speed and Testcontainers for Postgres and SQL Server. Docker for the container tier; skipped with an explicit message when absent.
TimeSeries.NET.Benchmarks Throughput per batch size, allocation during a fit, the 10⁸-row synthetic run. Run on demand, not in CI's critical path.

Simulated series are generated from a seeded PRNG committed with the tests, so parameter-recovery failures are reproducible rather than flaky. The statsmodels constants live in reference/ alongside the script that produced them — a reference value nobody can regenerate is a magic number, not a test.

Contract tests as a reusable asset

Adapter conformance is written once against ITimeSeriesSource and run against every implementation, including the in-core ArraySource. A contributor adding a ClickHouse source inherits the whole suite by implementing the interface, and any behaviour the core relies on is checked for their adapter too.

Section 11Decision log

The architectural choices that would otherwise get relitigated, with what each one costs.

ADR-001

Accumulators, not matrices Accepted

Estimation consumes mergeable summary state rather than a design matrix. Because X′X is (p+q+1)² regardless of row count, so the series never has to exist in memory. Cost: the normal-equations formulation squares the condition number, mitigated by column scaling and an optional ridge.

ADR-002

Ports in the core, adapters outside Accepted

The source interfaces are declared by the core and implemented by satellite packages. Because it is the only way the core reads from Postgres while depending on nothing. Cost: one extra package to publish per non-ADO.NET store.

ADR-003

Batched cursor rather than IAsyncEnumerable<double> Accepted

The engine pulls batches; IAsyncEnumerable is a public convenience wrapper. Because per-item async overhead is seconds at 10⁸ rows against a few seconds of real arithmetic. Cost: adapter authors implement two small interfaces instead of one iterator.

ADR-004

Single-pass Hannan–Rissanen via a lag-augmented Gram matrix Accepted

Both HR stages are linear in the same lagged values, so one accumulator serves both. Because it removes the second traversal, makes incremental folding exactly equal to batch refitting, and makes grid search free. Cost: HR's stage-three refinement is excluded, and ACF/PACF need their own Toeplitz-correct accumulator alongside.

ADR-005

DbDataReader as the universal SQL adapter Accepted

One adapter against the BCL base class rather than one package per database. Because every major .NET SQL driver derives from it, and the consumer already references their own. Cost: no provider-specific optimisations, and Mongo still needs its own package.

ADR-006

Immutable fit separate from the estimator Accepted

ArimaModel is stateless and produces an immutable ArimaFit, rather than the fit-then-forecast object sketched in the README. Because the fit must be serialisable, cacheable and thread-safe, and mutable model state makes all three awkward. Cost: the README sample changes before anyone depends on it.

ADR-007

Consumer supplies the SQL Accepted

The library opens a cursor over an ordered result set; it does not generate queries. Because anything more becomes an ORM that is wrong for somebody's schema and cannot be tested against schemas it has never seen. Cost: a slightly longer first example, and the consumer owns their own index.
