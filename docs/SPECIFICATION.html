Section 01Scope

One library, installed by the consumer, that fits an ARIMA or ARIMAX model to a series and returns a forecast over a caller-supplied horizon. The consumer's data never leaves their process.

1.1In scope

  • ARIMA(p,d,q) and ARIMAX — the same estimator, exogenous regressors optional. Non-seasonal and seasonally differenced, written (1−B)d(1−Bs)D.
  • Estimation by Hannan–Rissanen: consistent, closed-form, no optimiser, no dependency.
  • Forecasting to an arbitrary horizon — expressed in periods or in calendar time — with prediction intervals.
  • Two fitting paths from one engine: in-memory arrays for ordinary data, and a streaming path that reads from the consumer's database without materialising the series.
  • Many-series fitting: one ordered scan, one model per key.
  • Automatic order selection over a (p,d,q) grid.
  • ACF, PACF, differencing, error metrics (MAE, MSE, RMSE, MAPE, sMAPE) as supported public surface.
  • Incremental refit: fold new observations into a saved model state.

1.2Not in scope for v1

  • Exact maximum likelihood. Hannan–Rissanen is the estimator. It is consistent and noisier than MLE on short series; this is a deliberate trade for having no optimiser and no dependency.
  • Seasonal AR/MA terms (the P, Q of SARIMA). Seasonal differencing ships in v1; seasonal polynomial terms are deferred.
  • ETS, Holt–Winters, state-space models. Roadmap, not v1.
  • Any hosted service, API, or dashboard. The library is the product.
  • Writing to the consumer's database. Reads only.
  • SQL generation. The consumer supplies the query; the library supplies the cursor. Anything more becomes an ORM that is wrong for somebody's schema and cannot be tested.

Section 02Packages and dependency rules

The zero-dependency promise is a selling point and is enforced structurally: only one package in the set is allowed a third-party reference.

PackageContainsDependencies
TimeSeries.NET Models, estimator, forecasting, transforms, accumulators, metrics, and the source interfaces. None.
TimeSeries.NET.Data DbTimeSeriesSource over System.Data.Common.DbDataReader. None — System.Data.Common is in the BCL.
TimeSeries.NET.Data.MongoDb Cursor source over an aggregation pipeline. MongoDB.Driver.
TimeSeries.NET.Extensions.DependencyInjection AddTimeSeries() registration helpers. Microsoft.Extensions.DependencyInjection.Abstractions.
Why one adapter covers most databases

Npgsql, Microsoft.Data.SqlClient, Microsoft.Data.Sqlite, MySqlConnector, Oracle.ManagedDataAccess, ClickHouse.Client and DuckDB.NET all derive from DbDataReader. A single adapter against that base class reaches every one of them and adds no dependency to anything. The consumer already references their own driver; the library never needs to. MongoDB is the only listed store whose cursor is not ADO.NET, so it is the only one that earns a package of its own.

2.1Namespace rename Decision 2

The current assembly is TimeSeries.Core with types under TimeSeries.Core.Math. That namespace shadows System.Math — which is why Differencing.cs has to spell out System.Math.Exp inside the library itself. Every consumer who writes using TimeSeries.Core.Math; inherits the same collision. Proposed:

Cheap now, breaking later. The NuGet package id is TimeSeries.NET regardless.

Section 03Public API surface

Three objects carry the whole library: options describe the model, an estimator produces a fit, and the fit produces forecasts. The fit holds no data, so it can be serialised, shipped, and forecast from anywhere.

3.2Estimator

Per the standing decision, one class covers ARIMA and ARIMAX — they are the same model, and the presence of exogenous columns is the only difference. This supersedes the ArimaxModel shown in the current README.

public sealed class ArimaModel
{
    public ArimaModel(ArimaOptions options);

    // In memory — synchronous, no allocation beyond the accumulators.
    public ArimaFit Fit(ReadOnlySpan<double> series);
    public ArimaFit Fit(ReadOnlySpan<double> series, ExogenousMatrix exogenous);

    // Streaming — the series is never materialised.
    public ValueTask<ArimaFit> FitAsync(IAsyncEnumerable<double> series, CancellationToken ct = default);
    public ValueTask<ArimaFit> FitAsync(ITimeSeriesSource source,        CancellationToken ct = default);

    // One ordered scan, one model per key.
    public IAsyncEnumerable<KeyedArimaFit> FitManyAsync(IGroupedTimeSeriesSource source,
                                                        CancellationToken ct = default);
}

The synchronous overloads are wrappers: they feed the same accumulators the streaming path uses. There is one estimation code path in the library, not two.

3.3Fitted model

public sealed class ArimaFit
{
    public ArimaOrder            Order               { get; }
    public SeasonalOrder         Seasonal            { get; }
    public ReadOnlyMemory<double> AutoRegressive      { get; }   // φ₁ … φₚ
    public ReadOnlyMemory<double> MovingAverage       { get; }   // θ₁ … θ_q
    public ReadOnlyMemory<double> ExogenousCoefficients { get; } // β
    public double                Intercept           { get; }
    public double                InnovationVariance  { get; }   // σ̂²
    public long                  ObservationCount    { get; }
    public ArimaDiagnostics      Diagnostics         { get; }
    public FitWindow             Window              { get; }   // what was fitted, for audit

    public ForecastResult Forecast(ForecastHorizon horizon, ForecastOptions? options = null);
    public ForecastResult Forecast(ForecastHorizon horizon, ExogenousMatrix future,
                                   ForecastOptions? options = null);

    public void WriteTo(Stream destination);
    public static ArimaFit ReadFrom(Stream source);
}

An ArimaFit for ARIMA(2,1,1) is roughly ten doubles plus a short tail of recent values — a few hundred bytes on the wire. It holds no reference to the series, the source, or the connection.

3.4End-to-end usage

var source = new DbTimeSeriesSource(
    () => new NpgsqlConnection(connectionString),
    new DbSeriesQuery
    {
        CommandText = """
            SELECT ts, close_px, vix
            FROM   market.daily_bars
            WHERE  symbol = @symbol AND ts >= @from AND ts < @to
            ORDER  BY ts
            """,
        ValueColumn      = "close_px",
        ExogenousColumns = ["vix"],
        TimeColumn       = "ts",

Console.WriteLine($"{next.Mean.Span[0]:F4}  [{next.Lower.Span[0]:F4}, {next.Upper.Span[0]:F4}]");

Section 04Estimation engine

Hannan–Rissanen is conventionally described as two regressions run in sequence, implying two passes over the data. It can be done in one, because both stages are linear in the same lagged values.

4.1The single accumulator

Stage two regresses yt on lagged y and on pilot residuals êt−j = yt−j − Σk φ̂k yt−j−k. Every regressor is therefore a linear combination of yt−1 … yt−L where L = max(p, q + m). Accumulate the lag-augmented Gram matrix over vt = (yt, …, yt−L):

G = Σ  v  v′        s = Σ  v         N = n − L
     t   t  t             t   t

Then, with A built from the pilot coefficients alone — column i of the AR block is ei, column j of the MA block is ej − Σk φ̂k ej+k:

Z′Z = A′ G A          Z′y = A′ G e₀          y′y = G[0,0]

The pilot AR(m) regression needs no separate work at all: its normal equations are the submatrix G[1..m, 1..m] with right-hand side G[1..m, 0]. Both stages, from one accumulator, in one pass.

The only concession is fixing both stages to the same row range t ∈ [L+1, n] rather than letting each start where it naturally could. On a series of 300 million rows that discards about 35 rows, and it makes the two stages mutually consistent rather than less so.

4.2Why autocovariances are accumulated separately

G is not Toeplitz. G[0,1] and G[1,2] share a lag distance but cover row ranges offset by one, so they differ. Durbin–Levinson requires a genuinely Toeplitz γ̂, and the divide-by-n estimator is positive semi-definite precisely because it is the classical one — which is the standing reason for choosing it.

So the pass feeds two accumulators, not one: G for regression, and the classical γ̂k sums each over their own natural range t ∈ [k+1, n] for ACF and PACF. They share a ring buffer, so the second costs L running sums and nothing else. Merging them would quietly destroy the stability property the biased estimator was chosen to provide.

4.3Parallel fitting of one long series

Partial G matrices merge by addition, so a long series can be fitted in parallel over row ranges. Lagged rows straddle partition boundaries, so each partition reads a warm-up prefix of exactly L rows before its start, uses them only to prime the ring buffer, and contributes none of them to G. The merged result is then identical to the single-pass result up to floating-point associativity. This is an asserted invariant, not an aspiration — see §11.

4.4What is excluded

Hannan–Rissanen's optional third-stage refinement filters y by the estimated ARMA polynomial — an infinite-order filter, not expressible as a finite Gram matrix. It would cost a genuine second pass or a truncation. Given that the reason for choosing HR was to avoid an optimiser, stage three is excluded and the documentation says so plainly.

Section 05Forecasting

The horizon is the caller's input, expressed either in periods or in calendar time. Intervals are not optional.

5.1Horizon

public readonly record struct ForecastHorizon
{
    public static ForecastHorizon Periods(int count);
    public static ForecastHorizon Days(int count);
    public static ForecastHorizon Months(int count);
    public static ForecastHorizon Years(double count);
}

Calendar horizons resolve against ArimaOptions.Frequency. Calling Years(2) without a declared frequency throws ForecastHorizonException rather than guessing — a library that silently assumes daily data when the series is monthly is worse than one that refuses.

5.2Recursion and integration

Point forecasts are produced by the standard recursion on the differenced scale: future innovations are zero, and residuals within the last q steps come from the fitted tail. The result is then integrated back through (1−Bs)D and (1−B)d using the integration state carried on the fit. For ARIMAX, future exogenous values are a required argument — the library will not extrapolate the consumer's regressors for them.

5.3Prediction intervals

Interval half-width at step h is zα · σ̂ · sqrt(Σj<h ψj²), with the ψ weights obtained from the AR and MA polynomials and then cumulated once per order of differencing. ForecastResult always carries Mean, Lower, Upper and StandardError; there is no point-only overload.

Design note — long horizons

An ARIMA point forecast converges to its drift line within a handful of steps. At a two- or three-year horizon the mean path is a straight line and carries almost no information; the interval width is the entire content of the forecast, and for d = 1 it grows roughly like h3⁄2. Making intervals mandatory is therefore a correctness decision, not a convenience. The documentation must state this rather than let a consumer read a flat line as a confident prediction.

Section 06Order selection

Because every candidate order is a different small matrix A applied to the same G, an entire grid search costs one pass over the data.

public sealed record AutoArimaOptions
{
    public int                  MaxP               { get; init; } = 5;
    public int                  MaxQ               { get; init; } = 5;
    public IReadOnlyList<int>   DifferenceOrders   { get; init; } = [0, 1, 2];
    public IReadOnlyList<SeasonalOrder> SeasonalCandidates { get; init; } = [SeasonalOrder.None];
    public InformationCriterion Criterion          { get; init; } = InformationCriterion.Aicc;
}

public sealed class AutoArima
{
    public ValueTask<ArimaSelection> SelectAsync(ITimeSeriesSource source, CancellationToken ct = default);
}

Differencing order changes the series itself, so each d (and each seasonal candidate) needs its own transform and its own G — but those run side by side off a single cursor. With MaxP = MaxQ = 5, m = 32 and three values of d, that is three matrices of 38 × 38, about 35 KB in total, to evaluate 108 candidate models on one scan.

Pilot order m comes free from the same matrix: AR(k) for every k ≤ MaxPilotOrder is a nested submatrix of G, so its residual sum of squares — and therefore its AICc — is available without touching data. Choosing m stops being a guess.

ArimaSelection returns the winning ArimaFit plus the full ranked table of candidates with their criteria, so the choice is inspectable rather than opaque.

Section 07Data access

The seam between the library and the consumer's database is a batched cursor. Nothing above it knows what a connection is.

7.1Interfaces (in core, zero dependency)

namespace TimeSeries.Data;

public interface ITimeSeriesSource
{
    int RegressorCount { get; }
    ValueTask<ITimeSeriesCursor> OpenAsync(CancellationToken ct = default);
}

public interface ITimeSeriesCursor : IAsyncDisposable
{
    ValueTask<bool> ReadAsync(CancellationToken ct = default);
    SeriesBatch Current { get; }
}

public readonly struct SeriesBatch
{
    public ReadOnlyMemory<double> Values     { get; }  // Count
    public ReadOnlyMemory<double> Exogenous  { get; }  // Count × RegressorCount, row-major
    public int Count { get; }
}

Batching is the reason this is not plain IAsyncEnumerable<double>. A buffered await foreach carries roughly 5–20 ns of state-machine overhead per item. At 300 million rows that is seconds of pure ceremony against a few seconds of actual arithmetic. Eight thousand rows per await amortises it away and leaves the inner loop a synchronous span loop the JIT can vectorise. IAsyncEnumerable<double> remains a public convenience overload, implemented on top of this.

7.2Reading at scale

  • No OFFSET pagination. OFFSET n is O(n) per page and turns a full scan into O(n²). Where paging is needed, the source uses keyset seeks: WHERE (key, ts) > (@lastKey, @lastTs) ORDER BY key, ts. Preferably it simply holds one ordered cursor open.
  • Sequential access. The reader is opened with CommandBehavior.SequentialAccess and columns are read in ordinal order.
  • Buffers are pooled. Batch buffers come from ArrayPool<double> and are returned on dispose. Steady-state allocation during a fit is zero.
  • Windows are explicit. Every fit records a closed [from, to) range in FitWindow. Single-pass estimation means this is not needed for consistency, but it gives the incremental watermark and an auditable statement of exactly what was fitted.

7.3Many series in one scan

Set KeyColumn and order by (key, time). Because keys arrive contiguously, exactly one series is in progress at a time, so working memory is O(L²) per worker, not per key — a million series costs the same as one. This requires a composite index on (key, time); without it the database sorts on disk and the problem moves rather than disappears. The source validates the ordering and throws on an out-of-order key rather than silently fitting a mixture.

7.4Gaps Decision 6

ARIMA assumes regular spacing, and at this volume missing observations are certain — holidays, halts, late-arriving rows. Detection belongs to the source, which sees timestamps; the core sees only values. DbSourceOptions.Gaps takes Throw (default), ForwardFill or Interpolate, evaluated against ExpectedStep. Defaulting to Throw makes a silently misaligned fit impossible.

Section 08Incremental refit

Because G, s and N are pure sums, folding new observations into a saved state gives a result identical to refitting from scratch over the union.

public sealed class IncrementalArima
{
    public IncrementalArima(ArimaOptions options);
    public static IncrementalArima Restore(Stream state, ArimaOptions options);

    public ValueTask FoldAsync(ITimeSeriesSource newRows, CancellationToken ct = default);
    public ArimaFit Solve();
    public void SaveTo(Stream destination);

    public FitWindow Watermark { get; }
}

Both the pilot coefficients and the ARMA coefficients are re-derived from the updated G with no data access, so there is no frozen pilot, no accumulated drift, and no refit cadence to tune. Batch and incremental are the same computation reached by different routes, and §11 asserts them equal.

ForgettingFactor remains available as a modelling choice: scaling G, s and N by λ before each fold ages older observations out at a chosen half-life. Useful where regimes shift; it is no longer compensating for anything.

Serialised state is (L+1)² + (L+1) + 2 doubles plus the ring-buffer tail and the window — about 12 KB at L = 37, small enough to live in a row of the consumer's own database.

Section 09Numerical contract

Accumulating cross-products squares the condition number. At financial scales that is a real hazard, and every mitigation here is cheap on a path that is I/O-bound.

HazardWhere it bitesMitigation
Catastrophic cancellation A price level near 40 000 with a daily deviation near 200; Σx²/n − x̄² loses most of its significant digits. Subtract a per-column offset captured at the first observation before accumulating. Algebraically exact, restores conditioning.
Squared condition number ARIMAX with regressors on different scales — a price level beside a 0/1 flag. Standardise columns using the first-pass moments; un-scale coefficients at solve time. Optional ridge remains available.
Drift over 10⁸ additions Long-running accumulation of G. Neumaier compensation, opt-in. Roughly 2× the flops on a path that is not compute-bound.
Singular design A constant differenced series — what any exact polynomial trend reduces to. Detected and short-circuited to a deterministic fit, per the standing decision.
Non-invertible MA roots Hannan–Rissanen on short or noisy series can land outside the invertible region. Roots are checked; the fit carries Diagnostics.IsInvertible and forecasting a non-invertible model raises a warning rather than returning quietly wrong intervals.

If normal equations plus column scaling prove insufficient in practice, the accumulator interface also admits a streaming QR by Givens rotations — still O(L²) state, still row-by-row, still mergeable by stacking two R factors and re-triangularising. It drops in behind the same seam without touching callers. Documented as an upgrade path, not built speculatively.

Section 11Testing and acceptance

There is no existing implementation to check against, so correctness has to be established from outside the library. Four independent layers, cheapest first.

  1. Closed-form identities. AR(1) has ρk = φk; MA(1) has ρ1 = θ/(1+θ²) and zero beyond; PACF of AR(p) cuts off after lag p. These need no reference implementation.
  2. Hand-computed fixtures. Five- to ten-point series with arithmetic worked out in the test file, covering differencing, integration, OLS and the metrics.
  3. Parameter recovery. Simulate from known (φ, θ, β), confirm estimates fall within two standard errors at n = 10⁴ and that the error shrinks as n grows. This tests the property Hannan–Rissanen actually promises.
  4. Reference values. Constants generated from statsmodels, committed together with the script that produced them so they can be regenerated and audited.

11.1Structural invariants

These catch the streaming-specific bugs the layers above cannot:

InvariantTolerance
Streaming fit ≡ in-memory fit1e−10 relative
Partitioned fit with warm-up ≡ single-pass fit1e−12 relative
Incremental fold ≡ batch over the unionExact equality of G, s, N
Difference → integrate round trip1e−12 absolute, property-tested over random series
Grid search reads the source exactly onceAsserted via a counting source
10⁸-row synthetic fit under a fixed memory ceiling< 64 MB working set

The counting-source assertion matters more than it looks: the one-pass property is the architectural claim of this design, and a refactor that quietly reintroduces a second scan would otherwise pass every other test.

Section 12Packaging

12.1Build requirements

  • Deterministic builds, ContinuousIntegrationBuild set in CI, SourceLink, and symbol packages (.snupkg) published alongside.
  • GenerateDocumentationFile on, warnings as errors, XML documentation on every public member — the library ships as a NuGet package and IntelliSense is its primary documentation surface.
  • Public API surface tracked by Microsoft.CodeAnalysis.PublicApiAnalyzers so a breaking change cannot pass review unnoticed.
  • PackageLicenseFile pointing at the custom licence, with the commercial path stated in the package description — consumers will see a non-OSI licence and need to know what to do about it.

12.2Target frameworks Decision 1

net8.0 is the primary target. The question is whether to multi-target for .NET Framework, which is still widespread in finance:

TargetReachesCost
net8.0.NET 8 and laterNone
netstandard2.1.NET Core 3.0+, Mono, Xamarin — not .NET FrameworkNone; adds little reach over net8.0
netstandard2.0.NET Framework 4.6.1+System.Memory and Microsoft.Bcl.AsyncInterfaces — ends the zero-dependency claim

Recommendation: ship net8.0 only for v1. Both extra dependencies are Microsoft-owned and unobjectionable in practice, but "no external dependencies" is on the front of the README and is worth more than .NET Framework reach until a consumer actually asks for it.

14.1Standing decisions carried forward

Recorded here so they are not relitigated: one ArimaModel covers ARIMA and ARIMAX; Hannan–Rissanen rather than exact MLE; biased divide-by-n autocovariance to keep the sequence positive semi-definite and Durbin–Levinson stable; MAPE throws on a zero actual; a constant differenced series is detected and short-circuited.
